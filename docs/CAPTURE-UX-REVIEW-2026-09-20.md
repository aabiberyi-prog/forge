# 截图编辑体验复查与修复

用户指出：窗口位置无法调整、一直置顶、文字不能二次编辑，并要求自行检查其余问题。本轮以截图编辑的六段流程为分析单元，全部检查；不是再次用“能够导出 PNG”代替可用性验收。

## 证据与修复

| 流程 | 现场证据 | 本轮结果 |
| --- | --- | --- |
| 1. 框选与确认 | 原流程主要依赖底部确认按钮，选择阶段没有 Enter / Esc 键盘处理。 | Enter 或双击进入编辑，Esc 取消；选择工具栏文字清晰可读。 |
| 2. 编辑窗口 | 原生读回：置顶 true、可缩放 false、系统边框 false；界面也没有拖动区。 | 编辑阶段恢复系统边框和任务栏入口，可缩放，默认不置顶；先调整尺寸再居中。原生位置设置为 (500,250)、客户区改为 1100×780 并读回成功。 |
| 3. 工具与属性 | 原界面有 23 个按钮、11 个 input 元素；所有工具的属性混在底部。未选按钮文字为 rgb(72,72,72)，低对比；数字字段缺少可见标签。 | 上方固定工具分组，选中态清楚；矩形显示 3 项相关属性，模糊 1 项，文字 4 项；字段均有可见标签。 |
| 4. 文字与对象编辑 | 文字工具仍激活时，双击已有文字先创建新的空对象；二次编辑框读回为空。 | 点击已有对象即可选择；文字可双击、按 Enter 或通过“编辑文字”按钮修改。已验证原文字读回、再次修改、移动后编辑；复制、删除、图层操作有明确按钮。Ctrl+拖动可在对象上继续绘制。 |
| 5. 裁剪与取消 | 原裁剪把标注渲染进位图并清空对象列表，之后无法继续修改原文字。 | 裁剪底图并平移保留的对象；实际裁剪后仍可取回和修改原文字。Esc 先取消选中；取消新文字不留下不可见空对象。 |
| 6. 完成与再次触发 | “保存”没有表达同时复制；输入控件内 Ctrl+S 未接入保存；再次截图会强行恢复全屏置顶。 | 明确“保存并复制”，输入控件内 Ctrl+S 可完成；再触发聚焦已有编辑窗口并保留编辑状态。 |

窗口问题也可能被误认为桌面自动化不支持拖动，但错误的窗口标志及缺失拖动区是独立可核对的证据。文字不能再编辑也可能由裁剪扁平化导致；本轮分别复现了“未裁剪时创建空文字”和“裁剪后对象丢失”，两条路径均修复。
